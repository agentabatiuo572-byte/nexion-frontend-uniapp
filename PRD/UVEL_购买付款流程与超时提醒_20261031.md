## 1. 选择支付方式

活动购机跨设备恢复时，新签发的等价报价优先沿用原可付款订单的报价。对升级前已保存不同报价号的会话，登录账号的建单成功回执或该建单命令的成功查询可返回 `recoveredQuoteId`。它须与本会话正在提交的报价号相同，回执的 `promotionQuoteId` 指向原订单报价。客户端核对订单号、金额、商品及数量、奖励条款后，在同一次账号存储写入中保存原报价指针、订单及命令结果。后续付款、取消和重开结账继续使用原订单。账号、命令目标或回执不匹配时保留原待核实命令。

- 底部弹层：标题「选择支付方式」，下方显示订单剩余时间（剩 mm:ss 订单自动关闭）；商品卡显示商品名、订单号、金额。普通结算、组合和活动结账的外部付款都带订单号和截止时间。
- 三个选项：钱包余额、银行卡支付、USDT。不出现支付密码字样，不出现服务商名称或域名。
- 钱包：显示可用余额；余额不足时在选项内显示「余额不足，还差 X USDT」和「去充值」，确认支付不可点。余额读不到时提示选择其他方式，不显示 0。
- 银行卡支付、USDT 是否显示取 `GET /api/app/purchase-payment-policy` 中各通道的 `configured`：未配置的通道不显示，界面不出现「暂不可用」「暂未开通」等文案；两个 USDT 网络都未配置时不显示 USDT。报价返回 `PURCHASE_PAYMENT_FEES_NOT_CONFIGURED` 时同样按未配置处理。
- 选 USDT 进入「选择网络」：USDT（ERC20）/ USDT（BEP20）两个选项卡，ERC20 排第一并默认选中，ERC20 未配置时默认 BEP20；每次从付款方式进入都按此默认。付款政策尚未读到时先按 ERC20 报价，若报价或随后读到的政策表明 ERC20 未配置，自动切到已配置的 BEP20 并重新报价；政策读取失败时，只把报价明确返回未配置的通道视为未配置（2026-11-03）。两个网络都确认未配置时回到付款方式页，USDT 不再显示，不停留在空的网络页（2026-11-04，BUG-069）。银行卡报价返回 503 `PURCHASE_PAYMENT_FEES_NOT_CONFIGURED` 或随后读到的政策确认未配置时，同样返回付款方式页并隐藏银行卡，不显示「暂不可用」「暂未开通」等提示，用户可继续选择钱包或已配置的 USDT；不创建付款单（2026-11-04，BUG-165）。各自显示商品金额、通道手续费、网络确认费和支付总额；ERC20 网络费由用户承担并计入总额；只显示已配置的网络，只配置一个时该选项占满整行。
- 选银行卡进入「银行卡付款」：和 USDT 网络页一样列出商品金额、通道手续费和支付总额，支付总额以美元 $ 显示；不显示越南盾金额和汇率，越南盾实付金额只在银行卡支付页面上显示（服务端仍按锁定汇率换算）。通道手续费取报价接口返回值，由后台按通道配置的费率加固定费计算，App 不自行计算。
- 单位：只有钱包余额和 USDT 路径显示 USDT；银行卡路径的金额一律用 $。钱包余额不足的提示只显示 USDT，不同时带 $（2026-11-04）。
- 费用明细精度（2026-11-03，BUG-085）：选择网络、银行卡付款和付款页的费用明细都按两位小数显示。「商品金额」取报价的 `subtotalUsdt`，即服务端已取两位的收款本金（业务本金 `businessAmountUsdt` 加舍入差额 `roundingAdjustmentUsdt`），各行相加等于支付总额；不单独显示舍入差额，也不显示六位业务本金（例：业务本金 342.135 显示「商品金额 342.14」）。App 不自行舍入。

## 2. 自动查询（不设手动按钮）

- 报价自动获取；只有网络失败和 5xx 才按 3/6/12 秒递增重试，最长间隔 30 秒，期间显示「网络不稳定，正在重试」。服务端的明确拒绝不重试：`ORDER_NOT_FOUND`、`ORDER_NOT_PAYABLE`、`ORDER_PAYMENT_EXPIRED` 按 §6 显示结论，其他拒绝按「订单信息变化」处理；通道未配置（503 `PURCHASE_PAYMENT_FEES_NOT_CONFIGURED`）仍按 §1 处理（2026-11-04，BUG-096）。报价到期前 30 秒自动换新。报价有效期只用于内部换新，界面只显示「报价 mm:ss 内有效，过期自动更新」。费用行的状态只在持有报价、读取中或重试中显示。
- 付款单每 5 秒自动查询；失败按 5/10/20/30 秒退避，并在状态条显示「网络已断开，恢复后自动确认付款」。已读到过的付款单返回 404 `PURCHASE_PAYMENT_INTENT_NOT_FOUND` 时停止查询，按 §6 处理（2026-11-04，BUG-095）；其他 404、网络失败和 5xx 不变。
- 切到后台（去钱包或银行 App 转账）只暂停查询，不关闭付款；回到前台立即查一次。离开当前页面时立即关闭该页的付款界面，记录保留，可从订单详情继续；离开的页面不会关闭下一页自动恢复的付款。
- 查不到付款单时，用原付款编号和原报价自动重新提交，服务端保证只生效一次。
- 不再有「重新查询」「查询支付结果」「继续提交本笔付款」等按钮。

## 3. 付款前提醒（居中弹窗，确认后才创建付款单）

- **2026-11-06，BUG-340、BUG-111 跟进**：普通购买、活动、组合和试用转购共用付款流程。打开提醒（含付款时间不足提示）时保存正在确认的支付总额、费用版本和方式。普通订单的总额须与确认值相同；试用转购按主文档 §9.11a 的确认上限执行：业务报价版本和费用版本不变、当前总额不高于已确认总额时直接继续，包括外部付款步骤及先下降后回升但仍未超过确认上限的情况，不随下降缩小原上限。版本变化或试用总额超过确认上限，以及普通订单总额变化时，银行卡、BEP20、ERC20 均撤下原提醒，显示「订单信息已更新 / 请重新确认后付款」及最新金额。「知道了」返回明细，须再次点击「前往付款」并确认提醒；提交前再次核对上述条件。只换报价编号且付款条件仍符合以上规则，保持静默。费用、金额计算及订单接口不变。

| 场景 | 标题 | 说明 | 按钮 |
|---|---|---|---|
| USDT（BEP20） | 请确认转账信息 | 仅通过 USDT（BEP20）· BSC 链转入，金额需为 X USDT；网络或金额错误将无法自动到账；外部钱包另收 BNB Gas | 我已了解，前往付款 / 返回 |
| USDT（ERC20） | 请确认转账信息 | 仅通过 USDT（ERC20）· 以太坊链转入，金额需为 X USDT；ERC20 网络费已计入总额，外部钱包另收 ETH Gas；以太坊确认较慢，请尽早付款 | 同上 |
| 银行卡支付 | 请确认付款信息 | 将打开银行卡支付页面，请按页面显示的金额一次付清，不要分次或修改金额；付款完成后会自动返回 | 同上 |
| 剩余不足 5 分钟 | 订单即将关闭 | 订单将在 N 分钟后关闭，银行或链上付款可能来不及到账，建议使用钱包余额支付 | 改用钱包 / 仍要继续 |

## 4. USDT 付款页

- **2026-11-06，BUG-354**：付款单尚未读到（包括创建丢响应、查询失败和跨页恢复）时，网络名称及风险提示沿用原待恢复记录的付款方式；ERC20 显示以太坊/ETH Gas，BEP20 显示 BSC/BNB Gas。读到原付款单后以其方式为准，不因尚无付款单误写成另一个网络。

- 全屏页，标题「USDT 付款」：应付金额（可复制）、倒计时「请在 mm:ss 内完成转账」、商品与订单号。
- 收款地址模块顶部为状态条：转动指示 +「等待到账 · 转账后自动确认」；最后 5 分钟倒计时与状态条变红（「等待到账 · 即将超时 · 超时将自动取消」）。下方为网络标签、二维码、地址（可复制）。
- 费用明细与风险提示（仅该网络转入、金额一致、错网无法找回、外部钱包另付 Gas）。
- 到账（`FUNDS_CONFIRMED`）后整页换成「已收到付款」状态页：不再显示二维码和地址；开通进度只标已到达节点；「可以离开此页，开通结果会通知你」与「查看订单」。交付（`DELIVERED`）后自动进入现有购买结果页。
- 返回键弹出「付款还在进行中 · 离开后可在订单详情继续付款，请勿重复付款」，继续付款 / 离开。

## 5. 银行卡支付页面

- 服务商不支持付款后跳回 App，所以在 App 内打开其支付页面：UVEL 顶栏（关闭、标题「银行卡支付」、订单关闭倒计时）、「安全支付页面」一行、底部「付款完成后将自动返回 UVEL」。只加载受信域名；银行 App 链接交给系统打开。App 端为原生子 webview，H5 端为内嵌页面。
- 付款单交付或离开等待状态时自动关闭支付页面。
- 关闭支付页面后进入「银行卡付款」页：应付金额（$，不提供复制）、倒计时、等待到账状态、费用明细（商品金额、通道手续费、支付总额，$）、提示；底部固定「重新打开支付页面」，回到同一张付款单、同一页面地址。
- 到账后「已收到付款」页的实付金额，以及购买结果页、订单详情结果卡上银行卡订单的已付金额，都以 $ 显示。
- 结果卡「已付金额」显示用户实际支付的总额：取订单的 `paidTotalUsdt`（含通道手续费和网络确认费，2 位小数；钱包订单等于订单金额）。购买结果页、订单详情结果卡和活动结账结果卡一致；活动结账的银行卡订单同样以 $ 显示（取订单的 `paymentMethod`）。服务端未返回 `paidTotalUsdt` 时显示订单金额（2026-11-02）。

## 6. 截止与异常（居中弹窗）

页面倒计时取付款单 `expiresAt` 与订单截止时间中较早者；按决策两者应同为下单后 30 分钟。

| 结果 | 标题 / 说明 | 按钮 |
|---|---|---|
| 超时（`EXPIRED`，原因非 `PAYMENT_FAILED`） | 付款超时，订单已取消 / 订单已超过付款时间并取消。如已付款，请勿重复付款，联系客服核对 | 重新下单 / 查看订单 |
| 银行卡付款失败（`EXPIRED` + `PAYMENT_FAILED`） | 银行付款未成功 / 可以重新付款或换一种方式 | 重新付款 / 换支付方式 |
| 金额不符等（`MANUAL_REVIEW`：`PAYMENT_AMOUNT_MISMATCH`、`PAYMENT_MULTIPLE_ARRIVALS`、`PAYMENT_BEFORE_ALLOCATION`、`PAYMENT_REORG_REVIEW`、`PAYMENT_TIME_UNVERIFIED`、`PAYMENT_REFUNDED_REVIEW`） | 付款正在确认中 / 付款金额与订单不一致（或：还需要一点时间确认），客服会协助处理，请勿再次付款 | 联系客服 / 查看订单 |
| 逾期到账（`PAYMENT_LATE_REVIEW`） | 收到一笔逾期付款 / 订单已超时关闭，客服会协助处理这笔付款 | 联系客服 / 查看订单 |
| 开通失败（其他人工处理原因） | 设备开通遇到问题 / 已收到付款，客服会协助完成开通 | 联系客服 / 查看订单 |
| 订单已过付款时间（报价或创建付款返回 `ORDER_PAYMENT_EXPIRED`，或已过订单截止时间） | 订单已过付款时间 / 这笔订单不能再付款，可以查看订单或重新下单 | 重新下单 / 查看订单 |
| 订单不可付款（报价或创建付款返回 `ORDER_NOT_PAYABLE`） | 订单已不能付款 / 这笔订单的状态已变化，可以查看订单或重新下单 | 重新下单 / 查看订单 |
| 订单不存在（报价或创建付款返回 `ORDER_NOT_FOUND`） | 找不到这笔订单 / 订单可能已不在你的账号中，可以重新下单 | 重新下单 / 关闭 |
| 付款记录不存在（已读到过的付款单返回 404 `PURCHASE_PAYMENT_INTENT_NOT_FOUND`） | 付款记录已失效 / 这笔付款记录已不存在，请到订单详情查看，不要重复付款 | 订单付款：查看订单 / 关闭；其他：知道了 |
| 订单信息变化（付款条件超出原确认或其他明确拒绝；试用金额上限见 §3） | 订单信息已更新 / 请重新确认后付款 | 订单付款：查看订单 / 关闭；其他：知道了 |
| 付款单创建前付款条件超出原确认（BUG-340；试用按 §3 同版本金额上限） | 订单信息已更新 / 请重新确认后付款 | 知道了：返回最新金额明细，再次确认 |
| 刷新后恢复的付款超时 | 同超时 | 查看订单 / 关闭 |
| 刷新后恢复的银行卡付款失败 | 同银行卡付款失败 | 订单付款：继续付款 / 查看订单；其他：知道了 / 关闭 |

- 「重新付款」：退役失败的付款单，订单付款编号轮换为新编号后重新报价；无法由本流程换号的入口（活动结账、试用转购、置换、容量）关闭付款流程，由原页面重新发起。
- 只有服务端确认该付款单已 `EXPIRED` 才能退役它并重新付款；本地倒计时结束、查询失败或处理中都不能代替（2026-11-03，BUG-081）。自动读取未找到付款单（包括已知付款单返回 404）时，不仅凭空结果释放待付记录、订单动作锁或轮换付款键；只有创建被明确拒绝且随后查询确证无付款单时，才按同键释放规则处理。仍有付款单、查询失败和结果未知均保留原记录（2026-11-07，BUG-351 合并跟进）。刷新后恢复的付款没有原页面的购买回调：「继续付款」回到原订单详情并重新读取订单和原付款命令后打开支付方式，包括活动订单。
- 「重新下单」：普通结算回到商品详情，组合回到组合页，活动结账回到活动商城入口；刷新后恢复的付款不提供重新下单。
- 活动结账中，付款界面里的去充值、联系客服、查看订单等跳转在活动结账结束本次付款、释放离开保护后进行（2026-11-03，BUG-081）。
- 上表的订单拒绝结束本次付款：提示背后不再保留付款弹层，提示给出去向；回到订单详情时重新读取订单（2026-11-04，BUG-096、BUG-095）。
- 创建付款时遇到订单拒绝：读取确认没有付款单后直接显示结论，不重新报价，所以断网或 5xx 不会回到重试。读取失败时保留原记录，不替换付款单，结论照常显示并停止查询；再次打开这笔付款时读取原单并沿用同键恢复，仅在明确拒绝且空查询后按同键释放规则处理。刷新后恢复的付款不提供重新下单，显示查看订单 / 关闭，订单不存在时只有关闭（2026-11-04）。
- **2026-11-07，自动读取合并**：已给出最终结论的本次付款停止定时器和后续查询/原单提交，不由后台读取重新打开方式页；冷恢复继续显示结论与查看订单出口。保留上游自动读取、居中 toast 及无手动查询的文案。
- **2026-11-06，BUG-351（含第三次跟进）**：外部付款被明确拒绝（如费用版本变化或报价过期），且随后成功查询证明没有付款单时，同步释放发起方同一付款键的待核实记录与当前结账会话状态。普通订单还须按相同动作键解除 `EXTERNAL` 付款锁并轮换付款键，不清除其他命令；有原页面回调时可重新确认新报价或切换钱包。重载后的冷恢复没有原购买回调，不再进入无法操作的方式页：复用已有订单拒绝结论，其他拒绝（包括 503 `PURCHASE_PAYMENT_FEES_NOT_CONFIGURED`）显示「订单信息已更新 / 请重新确认后付款」，通过「查看订单」回到原订单。丢失响应、普通 5xx、查询失败或仍有付款单时，保留原锁、原键、原报价及恢复流程。通道未配置 503 在有原页面回调时继续按 §1 回退：隐藏未配置通道，保留钱包及已配置的 USDT，仍使用原 `retire`，不额外释放订单动作锁；该回退不能使冷恢复进入无效方式页。
- 付款单已是 `EXPIRED` 或 `MANUAL_REVIEW` 时，USDT 与银行卡付款页和提示说同一结论：显示同一标题和说明，金额标签改为「支付总额」，不再显示倒计时、「请尽快完成付款」「正在生成收款信息」、复制金额、风险提示和「重新打开支付页面」（2026-11-04，BUG-097）。
- 活动结账和新组合购买（组合走活动结账）的钱包付款被服务端明确拒绝时：读取原付款命令确认未成交后，弹窗说明原因，可保留或取消订单，不显示「付款结果尚未确认」。服务端以错误码作为 HTTP 状态返回拒绝；5xx 和网络失败仍按结果未知处理（2026-11-04）。
- 支付密码框打开期间订单到期：提交时不发起支付，提示「订单信息已更新，请重新确认后支付」（2026-11-04）。
- 面向用户的文案不使用「人工核对 / 人工审核 / under review」等内部用语。
- 迟到款只进人工处理，不自动退款、不自动入钱包。

## 7. 订单详情与充值

- **2026-11-06，BUG-351 跟进四**：付款明确拒绝且空查询证明已释放原动作锁后，订单详情同步重读相同付款键的动作记录，立即移除旧待确认横幅；未知结果时沿用上游「正在确认支付结果」及自动读取，不提供手动查询按钮；丢响应或结果仍未知时不因此移除恢复提示。只更新现有页面记录，不新增付款状态 store。

- 订单详情所有状态的操作放在页面底部固定操作栏：待支付（取消订单 / 继续支付）、已激活（再买一单 / 去收益页查看）、已入仓（再买一单 / 设备仓库）、失败与到期（再次购买 / 复制订单号并联系支持）、已取消（再次购买）。首卡只保留状态、说明与进度。
- 进度轨：已完成、进行中、已中止的节点显示文案；未到达的节点只显示圆点，读屏跳过。
- 外部付款进行中：首卡提示「付款进行中 · 剩 N 分钟」，底部「继续付款」回到同一张付款单，不再走钱包防重恢复，也不显示手动「继续查询」卡片和底部浮动条。
- 付款入口遇到同一订单正在进行的读取（例如刚回到前台的刷新）时，不报「暂时无法查询」，等该次读取完成后继续打开支付方式。
- 外部付款进行中点「取消订单」：不发取消请求，居中提示「付款进行中，暂不能取消 · 这笔订单正在付款中。已转账请等待确认；未付款的订单到截止时间会自动取消」，按钮「继续付款 / 知道了」。后端对付款中的取消返回 409 `ORDER_EXTERNAL_PAYMENT_IN_PROGRESS`（后端 B09）。
- 去充值：充值页顶部显示「为订单充值 · 还差 X USDT · 订单 mm:ss 后自动关闭」；余额足够后横幅变为「余额已到账」，底部固定「返回继续支付」，回到订单并自动打开支付方式（默认钱包）。余额未读到时不显示差额。
- 命名：银行卡通道在付款方式、付款结果、充值入口统一叫「银行卡支付」，充值记录类型为「银行卡充值」。
- 充值页同样只显示已配置的通道和网络，不显示「暂不可用」类文案（2026-11-02，规则见主文档 §9.2.1、§9.2.3、§9.2.4）。

## 8. 依赖后端（uvel-docs handoffs 20 B2）

- 付款单过期时间 = 订单截止时间（下单后 30 分钟），报价有效期不超过截止时间。
- 截止且宽限期内未到账：同一事务取消订单（`PAYMENT_TIMEOUT`），退还库存、额度与优惠券。
- 银行卡支付失败（服务商状态 5）：付款单结束为 `EXPIRED` + `PAYMENT_FAILED`；订单换新付款编号后再次提交应视为新付款，不得当作失败单的幂等重放。状态 4（已退款）转人工。
- 进入人工处理时必须带原因码；已有：金额不符、多笔到账、分配前到账、重组、逾期。
- 自动关单不得关掉进行中的直付付款单（后端 test `971fb9c8` 已处理取消与直付互斥，见后端 PRD B09）。
- 订单投影（`GET /api/orders`、订单详情、外部付款回执、活动订单）增加可选字段 `paidTotalUsdt`（2 位小数字符串，实付总额含通道手续费和网络确认费；钱包等于 `amountUsdt`）。App 已按可选字段解析；后端 `origin/test` 已提供该字段，未付款时可为空，结果卡缺省时仍显示订单金额（2026-11-04，BUG-165）。
