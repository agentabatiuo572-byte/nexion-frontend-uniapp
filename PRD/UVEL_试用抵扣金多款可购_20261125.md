# 试用抵扣金可购买多款设备

权威：正式后端 `GET /api/trial/purchase-options`、`GET /api/trial/state`、`POST /api/trial/convert` 与外部付款接口（后端 B90 已交付，接口契约见 uvel-docs 后端接口说明 PRD-B90-trial-purchase-options）。商品清单、金额、确认版本、能否购买都由接口决定；客户端只显示服务端报价并回传确认版本。界面写法见 design-system 04「试用详情与试用抵扣购买」与 03「单选行」。

#### [FEAT-TRIAL06] 用试用抵扣金任选一款设备

**① 用户故事**：作为正在试用或在可抵扣期的用户，我想用试用抵扣金从运营给出的几款设备里任选一款买下，以便买到最合适的设备，而不只能买正在试用的那台。

**② 验收(GWT)+异常路径**

入口与买的是哪一款（A = 本人这次试用的设备，B = 清单里的其他设备；商城普通入口指单件、无券、无活动）：

| 入口 | 买 A | 买 B |
|---|---|---|
| 试用入口（试用详情「抵扣购机」、商品详情「用试用抵扣金购买」） | 试用转购，付抵后金额，试用结束 | 试用转购，付抵后金额，试用结束 |
| 商城普通入口「立即购买」 | 试用转购（现行规则） | 全价普通购买，试用保留；机位满时入仓库 |

已有进行中的原购买时：再发起任何试用转购（含商城普通入口买 A）都打开原购买、不能再提交；商城普通入口买 B 照常全价购买。

- Given 清单里除 A 外还有 B、首次进入且没有预选 When 打开试用详情 Then 头部下出现选择区：标题「专享限时折扣设备」，说明「任选一款，价格已抵扣 · 新设备接替试用机位」；A 在第一行带「本次试用」，其余按售价从低到高；可买的行显示设备图、名称、抵后应付与划线售价，商品目录有预估的再显示预估每日收益；不可买的行写原因、不显示价格；单款报价失败的金额写「—」。至少一款 B 可买时，列表下写「其他设备仅支持余额支付」。默认选 A，A 不可买时选第一款可买的。
- Given 从商城某款进来，或同一领取单上次选过某款 When 进入 Then 选那一款；它已失效则提示「该设备已不可选，请重新选择」并停在未选，不替用户换。等待重选时即使只剩 A 也保留这一行。清单只有 A 且不在等待重选时不出现选择区。
- Given 换选 When 选中 B Then 票据与底部按钮「抵扣购机 · 应付」同步为该款报价；实际立减显示大于 0 时标题写设备名和立减，否则票据首行写设备名，可抵扣期保留到期提醒标题。
- Given 键盘操作 When Tab 进入选择区 Then 停在选中行（无选中时停在第一个可选行），方向键跳过不可选行，「查看购买条件 ›」单独聚焦且激活不改变选择。
- Given A 与 B 的购买条件 When 判定能否购买 Then A 只看阶段开放和该款硬件名额；B 另与商城普通购买用同一套购买条件、名额和限购账，只在付款时扣减；读取清单不占用限购、库存、名额。B 缺货显示不可选，B 下架不显示；A 下架或售罄仍在首行并写原因。运营之后改试用目标或把 A 加进清单，老用户仍只有一行 A，锁定价与三种付款方式不变。
- Given 选 B 并点「抵扣购机」 When 进入结算 Then 只能用余额，确认后直接输入支付密码；数量固定 1 台（Cloud Share 为 1 份）；不可用代金券、置换；折扣只在「核对订单」里列一次；托盘写「本单使用试用抵扣金，购买后试用结束」。选 A 时三种付款方式照旧。
- Given 余额转购成交 When 回执到达 Then 重新读取试用状态后进入购买结果；确认金额（两位）、订单实付与钱包扣款（六位）、购后到账 USDT 与 UVT 逐笔对得上；订单、结果页、设备页、赚取页、后台试用记录（试用设备 A、购买设备 B）都认得所买设备，B 下架或退款后仍认得；试用结束、机位数不变；同一账号不能再领取试用。
- Given 金额边界 When 应付为 0.000000／0.004999／0.005000 Then 依次为：验支付密码成交且没有扣款流水；显示 0.00、按六位核余额并扣款，余额为 0 时写「不足 0.01 USDT」；确认金额 0.01。显示尾差：总折扣额 = 两位售价 − 两位应付，尾差落在「试用抵扣金」行，没有该行时落在「试用期折扣」行，试用详情与结算一致，不影响六位结算。
- Given 单价涨或降、优惠政策变了（两位金额可能相同）When 提交 Then 要用户再确认一次：金额变了写新价划旧价，金额没变写「购买优惠已更新，请重新确认」；只是累计抵扣增加让应付变低时按原版本直接继续。
- Given 商城 When 在可用抵扣金购买的时间内浏览 Then 当前可买的 B 在商品卡显示「可用试用抵扣金」，详情有「用试用抵扣金购买」入口和托盘说明；A、从活动或代金券入口打开的、已有进行中的原购买时都不显示。
- 异常1（首次读取）：Given 清单首次读取中或首次读取失败 When 在试用详情 Then 票据按 A 的报价显示（预选别款时先收起），底部为灰色无金额的「抵扣购机」，失败时按钮上方写「设备信息加载失败，正在重试」并自动重读；本机记得这次试用的清单里有其他设备时选择区用静止占位行，不记得时先不显示，读到再出现。
- 异常2（刷新失败）：Given 同账号同领取单已有清单 When 刷新中或刷新失败 Then 保留原来的行、所选设备、票据和按钮，自动重读；旧报价只用于显示，进入结算前重新核对，核对不到就停在原处。
- 异常3（某款不可买）：Given 缺货、名额用完、不具备购买资格或报价读取失败 When 显示 Then 只有那一行不可选并写原因，资格原因带「查看购买条件 ›」（商品详情可达时）。全部不可买时底部为灰色无金额的「抵扣购机」，按钮上方写「暂无可购买的设备，试用照常进行」，可抵扣期写「暂无可购买的设备，试用收益仍保留」；清单只有 A 时写 A 自己的原因。
- 异常4（所选失效）：Given 已选设备被下架、移出清单或变为不可买 When 回到前台、进入结算或提交时重新读取 Then 提示「该设备已不可选，请重新选择」并清空选择（票据收起，底部灰色「请选择设备」）；单行暂时读不到不算失效，保留选择。
- 异常5（提交被拒）：Given 下架或移出、售罄、名额、资格、余额不足、暂时无法购买 When 回执到达 Then 前四类提示原因并可重选；余额不足写差额与「去充值」；「暂时无法购买，请稍后再试」不写原因；本次提交释放。首次被拒与按原提交号查回的拒绝走同一出口。
- 异常6（去充值）：Given 从试用结算去充值 When 部分到账或改价后仍不够 Then 留在充值页显示按最新应付的差额；余额够付最新应付才出现「返回继续支付」，回到同一设备的试用结算并重新核对；刷新或重开 App 后仍能返回；换账号不带出旧目标；已有进行中的付款走原付款，已成交进订单，试用结束回试用详情，设备失效回重选，读取失败继续等待。
- 异常7（原购买进行中）：选择区上方单独一张「进行中的付款」卡，设备、方式、金额、状态取自这笔付款；清单锁定、不显示票据；设备管理原位写「付款中，不能取消试用」。

| 原购买 | 状态显示 | 按钮 |
|---|---|---|
| A 的外部付款待支付 | 待支付 · 倒计时 | 继续支付（原付款单） |
| A 的外部付款已付出或待确认 | 结果确认中 | 查看进度（原付款单） |
| 余额付款，查询返回可用原提交号继续 | 未完成 | 继续支付：同一领取单、原提交号、原商品、金额与版本，用户重新输入支付密码，不自动重扣 |
| 余额付款，不能续付 | 结果确认中 | 查看进度（留在本页自动只读查询） |

本机未送达的提交只在权威状态仍可转购、本机有完整原参数时才可续付；试用结束或别处已成交时以权威结果为准。清单读不到、设备已移出时这张卡照样显示。

- 异常8（原外部付款终结）：Given 原外部付款查询 When 未付已终结 Then 付款已结束，不再锁定；When 确实迟付且确认宽限已过 Then 写「付款晚于截止时间，设备不会交付。款项将原路退回。」并可「更换设备」；When 已交付 Then 打开原订单；When 已退款 Then 显示原退款结果。前两种仅在领取单仍可转购时可以重选，已有新的原购买时按新的恢复。宽限内、查询结果未知、没有明确结果的保持「结果确认中」，不用本机时间推断；不出现「复核」一类内部说法。
- 异常9（后端兼容）：接口不存在（404 且不是 `USER_NOT_FOUND`）按单设备流程只买 A，商城不出现标签和入口，带试用标记的 B 回试用详情、不落到普通结算；`404 USER_NOT_FOUND` 是读取失败；`409 TRIAL_NOT_CONVERTIBLE` 重读试用状态进入实际终态。单设备流程下，底部按钮「抵扣购机 · 应付」、头部与票据文案、试用结算不设「优惠」组同样生效。

**③ 数据字典+生成规则**

| 字段 | 类型 | 生成规则/约束 |
|---|---|---|
| claimNo/serverTime/options | string/ISO 8601/array | 可购设备接口返回；A 始终在首行；B 下架或被拦时不返回，售罄返回但不可买 |
| productNo/name/imageUrl/productType/inventoryMode | string/enum | 服务端商品资料，imageUrl 可空；A 下架后仍有名称、售价 |
| originalTrialProduct/paymentMethods | bool/array | 是否 A；付款方式由服务端给，B 只有 WALLET |
| priceUsdt/storePriceUsdt | decimal string | A 为领取时锁定价，另给商城现价 storePriceUsdt（只在 A 行、可空，不同时标「领取时价格」）；B 为商城现价 |
| canPurchase/unavailableReason | bool/code | 服务端判定；客户端按原因码归类到商城已有文案，不自行推断能否购买，不显示原始码 |
| quote.amountUsdt 等 | decimal string（六位） | 显示取两位；是否为 0、余额是否够用按六位判断 |
| quoteVersion | string | 确认版本，转购与外部付款取报价必须回传；单价或优惠变化时变化。某款报价异常时 quote 与 quoteVersion 可缺 |
| originalPurchase | object/null | 进行中的原购买：kind 为 BALANCE（commandKey）或 EXTERNAL（intentNo），带设备、付款方式、确认金额、状态 |
| purchasedDevice | object/null，可缺 | 已转购时所买设备：编号、名称取成交订单商品，图按商品编号现取、可空 |
| canResumeSameKey | bool | 原余额提交能否按原提交号重新验密继续 |
| trialPurchaseOutcome | enum，可缺 | 原外部付款的终结结果：UNPAID_TERMINAL、LATE_PAYMENT_REVIEW；已交付、已退款看付款单自己的状态；其余没有结果的按仍在进行处理 |
| 预选设备 | 本地 | 按账号＋领取单记住，只用于回到试用详情时预选；同一行记住清单里有没有其他设备 |

**④ 状态机+禁止动作**
沿 FEAT-TRIAL03 的生命周期。选择区状态：未支持（404）→ 单设备旧流程；读取中 → 就绪／失败（自动重读）；就绪下选中、未选（等待重选）、全部不可买；有进行中的原购买时锁定。提交：提交中 → 成交／明确被拒（释放）／结果未知（只按原提交号查询）／可用原提交号续付（用户重新验密后）。禁止：客户端推算金额；读取失败当作下架或应付 0；提交后自动换成别的设备；结果未知期间对别的设备发起转购；从活动或代金券入口用试用抵扣金。

**⑤ 多状态覆盖**
默认（多款、A 选中）、选中 B、选中 Cloud Share（应付可能很低或为 0）、可抵扣期（无立减标题，票据首行写设备名）、领取价与现价不同、单项不可买、单项报价失败、清单读取中与持续失败、全部不可买、所选失效、进行中的付款四种、结算报价读取中与失败、余额不足与不足 0.01、价格变化与仅优惠变化、应付为 0、充值返回、后端未支持。极限态：长设备名、360 宽、9 种语言、明暗主题。

**⑥ 点击流矩阵**

| 触发 | 目标 | 反馈 |
|---|---|---|
| 首页、设备页、赚取页试用入口 | /pages/me/trial | 入口和文字不变（试用中「提前购买」，可抵扣期「抵扣购机」） |
| 选择区单选行 | 原地选中 | 票据与按钮同步该款报价 |
| 「查看购买条件 ›」 | 商品详情 | 只在详情可达时出现 |
| 「抵扣购机 · 应付」 | /pages/store/checkout?source=trial&product=<编号> | 进入该款的试用结算 |
| 结算「更换设备 ›」 | 试用详情选择区 | 保留当前选择 |
| 结算「去充值」 | 充值页（带返回目标） | 到账后「返回继续支付」回同一设备的试用结算并重新核对 |
| 商品卡（带标签） | 商品详情 | 详情里有抵扣入口 |
| 详情「用试用抵扣金购买」 | /pages/me/trial?product=<编号> | 进入试用详情并预选该款 |
| 详情「立即购买」 | B 普通结算；A 试用转购 | 按入口表；B 原价、不结束试用（机位满时入仓库） |
| 「继续支付」／「查看进度」 | 原付款 | 按原身份恢复 |
