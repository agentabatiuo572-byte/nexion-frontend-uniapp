# UVEL 购机活动落地页（App）

> **H5 Lite（2026-11-03）**：Lite 采用本页同一设计与规则。差异：按明确商品身份（`kind=phone` 或已知手机 SKU `phone` / `phone-basic` / `iphone15`，不按名称）隐藏手机商品卡、机型图和购买按钮，不能从落地页发起手机商品的新购买；SHARE 与已知硬件 SKU 照常展示。见主 PRD §6.11、§11.10。

日期：2026-11-01　设计稿：P-58（活动列表三种卡片、购机赠礼、首购礼、老用户加购、资格与时间状态）

## 1. 范围

三个购机活动模板各有一张专属落地页：

| 模板 | 页面标题（导航） | 列表卡片 |
|---|---|---|
| `SKU_GIFT` 购机赠礼 | 购机赠礼 | 赠礼海报卡 |
| `FIRST_PURCHASE` 首购礼 | 首购礼 | 首购票券卡 |
| `REPURCHASE` 复购召回 | 老用户加购 | 复购卡（标题用活动标题，演示为“老用户加购礼”） |

其他模板（`DIRECT_REFERRAL`、`MULTI_PRODUCT`）的卡片、入口和商城筛选不变。商城、商品详情、结算和下单行为不变。

## 2. 入口与路由

- 路由：`/pages/events/promotion-detail?id=<activityId>`，自定义导航。
- 活动页“购机活动”列表：三种模板点整张卡进入落地页；卡上“活动说明 ›”仍打开原说明弹层，不跳转。
- 首页活动轮播：三种模板点击进入落地页，轮播视觉不变；其他模板仍进 `pages/store/store?activityId=`。
- 落地页读到的模板不是这三种时，替换跳转到原商城筛选页。
- 未登录可访问：带 `id` 的落地页与 `store/detail?activityId=` 一样属于公开活动路由，全局守卫不拦截。

## 3. 数据来源

- 活动：`GET /api/promotions/{activityId}`（`promotionApi.get`，已登录带凭证）。账号切换清空后重读；语言切换重读；读取防串改沿用 `createPromotionReadFence` 与“账号 + 语言”身份核对。
- 商品名、价格、规格、机型图：已登录时读商品目录；未登录时公开接口拿不到目录，只显示内置机型图，商品名退回为赠品的 `deviceName` 或商品编号，价格不显示（底部栏改为奖励摘要）。
- 我的设备：只读 App 现有的设备快照（`app.devices`，有快照才显示），不另发请求。未登录或没有快照时，“我的设备”整行和台数隐藏。

## 4. 页面内容与字段对应

### 4.1 共用

- 阶段：`ACTIVE` 为进行中，`SCHEDULED` 为未开始，`PAUSED` 为已暂停，其余为已结束。已暂停沿用已结束的页面结构和底部按钮，购买入口同样关闭，只有标签和说明行不同（2026-11-04，BUG-037）。公开接口对未登录访问返回 `SIGN_IN_REQUIRED`；已登录时非 `ACTIVE` 活动返回 `INELIGIBLE`，所以资格拒绝只在进行中使用；未开始只显示时间状态（2026-11-04，BUG-165）。
- 状态页（未登录、不符合、未开始、已暂停、已结束）按状态板构图：不显示副标题和顶栏规则按钮，正文里的“完整规则 ›”保留。
- 奖励类型：`DISCOUNT_USDT` 是订单立减，统一用现有三语“订单立减”文案显示，不写“得 / 送 / 自动发放、在我的奖励查看”；首购第三步改为“结算直接抵扣”。

- 顶部标签：活动进行中时显示资格标签和剩余天数；未开始只显示品牌标签“{开始时间 · UTC} 开始”；已暂停只显示中性标签“活动暂停”；已结束只显示中性标签“已结束”。
  - `ESTIMATE_ELIGIBLE`：成功色标签，“符合参与条件 / 符合首购条件 / 符合加购条件”。
  - `INELIGIBLE`：中性标签，“暂不符合参与条件 / 不符合首购条件 / 需先完成一笔购机”。
  - `SIGN_IN_REQUIRED`：中性标签“登录后确认资格”。
  - `UNKNOWN`：不放资格标签。
  - 剩余天数沿用现有规则：服务端 `serverTime` 对 `endsAt`，不足一天“今日结束”，否则向上取整“剩 N 天”。
- 说明行：已暂停写“活动已暂停，暂停期间下单不参与本活动。”，不写结束时间（九种语言）。已结束写“活动已于 {endsAt · UTC} 结束，新订单不再赠送／不再发放奖励”。否则 `eligibilityMessage` 不为空时显示它；为空且 `INELIGIBLE` 时显示 App 三语模板文案（赠礼、首购各一句；复购的说明写在设备玻璃板里）。公开接口目前固定返回 `eligibilityMessage = null`。
- 活动时间：`{startsAt} – {endsAt} · UTC`，格式同 `displayDeadline`。
- 右上“活动规则”玻璃圆钮、各区“完整规则 ›”：打开现有 `PromotionTerms`，内容与活动列表的说明弹层一致。

### 4.2 购机赠礼

| 区块 | 字段 |
|---|---|
| 标题 / 副标题 | `title`；副标题为静态文案 |
| 机器舞台 | 第一条规则：主购 `productNo` 大图，赠品 `giftProductNo` 小图；赠品为 USDT/UVT 时右侧改为奖励金额。未登录时去掉礼物徽章；已结束时去掉氛围光、徽章和购买 / 赠送标签，设备灰度半透明 |
| 规则（每条规则一张票券） | 存在 `DISCOUNT_USDT` 买家奖励时标题为九语「活动规则」，其他赠礼标题为「赠送规则」（2026-11-04，BUG-165）。买：`productNo`、`minBuyQty` 台；送：赠品名 `disclosure.deviceName` 与 `quantity` 份（或金额 + 单位）；计奖方式：`repeatMode` + `minBuyQty`（每单 1 次 / 满 N 台每单 1 次 / 每 N 台 1 次）；每单上限 `maxGroups`、每人上限 `maxGroupsPerPerson`，`UNLIMITED` 显示“不限” |
| 赠品权益（仅 `DEVICE` 且 `disclosure.deviceRights` 不为空） | `durationDays`（空为“长期”）、`effectiveOn`（发放即生效 / 激活后生效）、`activationMode`（自动 / 手动激活）、`taskEnabled`（可参与 / 不参与）、`countsAsDeviceHolding` / `countsForRank` / `transferable` / `exchangeable` 打勾或打叉 |
| 到账与退款 | 第一条规则奖励的 `disclosure.terms`、`refundTerms`（当前语言，相同则只显示一次）、活动时间、脚注“参与资格以下单时的结果为准。” |

### 4.3 首购礼

| 区块 | 字段 |
|---|---|
| 首单奖励票券 | 第一条规则买家奖励的金额 + 单位（`DEVICE` 显示设备名）；存根“每人限 N 次”，N 为 `maxGroupsPerPerson`，不限时“不限次数” |
| 倒计时 | 进行中倒数到 `endsAt`、未开始倒数到 `startsAt`，格式 `6d 23h:41`，冒号闪动；按读取时的服务端时间推算；页面隐藏时暂停，减少动态时静止 |
| 未开始标签 | “{MM/DD HH:mm} 开始”（UTC，越南语日/月，英语 `Nov 8 10:00`） |
| 三步说明 | 静态三语文案 |
| 活动设备 | 每个 `productNos` 一张卡：名称、规格、价格、机型图，标签“首单得 {奖励}”；点击进商品详情并带活动上下文 |
| 规则要点 | 限额一句（`maxGroupsPerPerson` + `maxGroups`）、买家奖励 `disclosure.terms`、活动时间、“完整规则 ›” |

不符合或已结束时票券金额置灰、存根写“不可参与”、不显示倒计时。

### 4.4 老用户加购

| 区块 | 字段 |
|---|---|
| 设备玻璃板 | “我的设备 N 台”：设备快照中除手机与电脑算力外的设备数；最多 3 个缩略图，超出在第三个缩略图上标“+N”。后接虚线空位放第一条规则的 `productNo` 机型图和 UVT 标签“+{奖励}”，下方“再添 {minBuyQty} 台 {机型}，额外得 {奖励}” |
| 不符合时 | 玻璃板保留“我的设备”行（已知设备数为 0 时显示“0 台”；有设备却不符合时不显示台数，避免和提示矛盾），改为灰色虚线空位 +“完成第一笔购机后，再添一台即可得 {奖励}”，只留蓝色氛围光 |
| 可加购设备 | 同首购礼的设备卡，标签“加购得 {奖励}” |
| 参与条件 | 静态文案“需已有一笔有效购机，取消或退款的订单不计入。”、限额一句、活动时间、“完整规则 ›” |

## 5. 底部固定栏（DS-30）

| 情况 | 左侧 | 按钮 |
|---|---|---|
| 进行中，符合 / 资格未知 | 单商品且有目录价：商品名 + 价格；首购礼、多商品或无价格：奖励摘要 | 主按钮 L：立即购买 / 去下首单 / 立即加购。单商品进 `promotionDetailHref(productNo, activityId)`，多商品进 `promotionStoreHref(activityId)` |
| `SIGN_IN_REQUIRED` | 同上 | 主按钮“登录后购买”，进 `/pages/login/login?return=<本页>` |
| `INELIGIBLE`（赠礼、首购） | — | 整宽中性玻璃“查看其他活动”，回活动页“购机活动” |
| `INELIGIBLE`（复购） | 列表里有进行中的 `FIRST_PURCHASE`（按 `nextCursor` 逐页读到第一个为止，BUG-036）：“首单另有奖励” | 主按钮“去看首购礼”进该首购落地页；没有（或活动列表读不到）时整宽主按钮“去商城看看” |
| `SCHEDULED` | “开始后可下单” | 主按钮置灰 50%“未开始” |
| 已暂停、已结束 | — | 整宽中性玻璃“查看其他活动” |

## 6. 读取状态

- 停留在页面期间到达开始或结束时间（按读取时的服务端时间偏移计算）时，自动重读一次，资格、标签和按钮随之更新；超过约 23 天的边界不设定时，下次回到页面时重读。

- 加载中：保持页面骨架（标签、标题、主卡占位）。
- 首次读取失败：主卡写“活动奖励 —”，就地“活动信息暂未读取 / 网络不稳定，稍后再试。”+ 文字按钮“重试”。
- 已有内容时刷新失败：保留原内容；会话被拒（401/403）时清空。

## 7. 动效

一次性入场（分段上浮、舞台机器入场、赠品标弹出、空位滑入、底部栏上滑），按压缩放 0.97；只有倒计时冒号持续循环；只动 transform 和 opacity；减少动态时全部静止，底部主按钮按下时同样不缩放（2026-11-04，BUG-038）。

## 8. 数据限制

- 公开活动接口没有首购的认定方式（以哪笔订单、何时付款、是否含赠品订单为准），页面只显示服务端给出的资格结论，三步说明为静态文案。
- 公开接口没有复购间隔（距上一笔购机多久可参与），页面不显示也不推算。
- `eligibilityMessage` 目前固定为 null，不符合 / 未登录的原因由 App 模板文案说明，只按模板区分，不区分具体原因。
- 商品目录需要登录，未登录时商品名与价格不可用（见 3）。
- 行为采集页面目录需后端追加迁移登记 `pages/events/promotion-detail`，登记前该页的行为事件会被后端拒收（不影响页面使用）。
