# 免费试用生命周期与算力队列

权威：正式后端 AppTrialLifecycleService 的 state/start/convert/cancel 与按原请求号查询的开通、取消回执。设备占槽规则归正式容量策略。商品、金额、时长、资格由接口发布配置和领取快照决定。

#### [FEAT-TRIAL03] 持续状态与提前购机

**① 用户故事**：作为已领取免费试用的用户，我想在首页持续查看状态并随时购机，以便在已累计抵扣范围内完成转购，无需等满试用期。

**② 验收(GWT)+异常路径**
- Given 可领取且有容量 When 打开确认 Then 展示产品、配置天数、预计抵扣，确认按钮明确激活并开始试用；取消不领取。When 确认 Then 先激活中，幂等请求及权威读回成功后展示成功反馈，刷新仍试用中。
- 领取只开通用户在弹层中确认的设备与条款。发出开通请求前复核商品 ID、设备名、试用天数、日收益依据和抵扣上限。任一项有变就在原弹层更新并提示一次，等用户再次确认才提交。旧请求已明确未受理时，条款变化后作废，用户再次确认时使用新请求号。旧请求结果仍未知时，系统继续按原请求号只读确认。原流程允许主动重试时，用户确认新条款后仍使用原请求号和原载荷。
- 后端在受理时绑定已确认商品及条款版本（B124）。App 提交弹层显示时的商品 ID 和条款版本，前后都有版本时也校验版本。服务端确定拒绝旧条款时保留原拒绝回执，领取与名额保持原状。App 结束旧命令，刷新资格及条款并提示，用户再次确认时使用新请求号。旧接口未提供版本时继续按设备名提交。
- Given 已结束且冷却已满 When 后台明确允许再次领取 Then 首页与详情可重新进入同一领取确认流程；读取失败或资格未确认不得开启下一轮。
- Given ACTIVE/GRACE When 返回首页 Then 状态卡保留；详情可提前购机，可购设备见 [FEAT-TRIAL06](UVEL_试用抵扣金多款可购_20261125.md)。Given REDEEMED Then 入口进入正式设备管理，原试用不再占槽。
- Given 运营设置小数购买折扣率 When 查看「我的试用」或进入商城试用转购结算 Then 折扣标签保留有效小数位（例如 0.15%、1%），折扣和实付金额以服务端报价为准（BUG-331）。
- Given 已领取生命周期状态 When 点击首页试用卡任意非重试区域或键盘激活卡片 Then 进入既有详情/设备管理目的地，不额外显示独立按钮；嵌套重试只刷新。未领取及未领取满容量状态保留原按钮和领取/管理权限。
- Given ACTIVE/GRACE When 首页展示状态卡 Then 状态标题后同一行显示 `2d 23h:44` 格式倒计时；按剩余分钟向下取整（不足一分钟显示 `0d 0h:00`），与「我的算力列队」和详情页同一方向（2026-11-04，BUG-028），未知显示“-”。到零只更新显示，不自行改变服务端生命周期或抵扣金额；完整本地化时间保留在无障碍名称中。两张福利卡等高，设备图位于卡片底部光影上方。
- 异常1：开通或取消结果未知时保持确认中，按原请求号只读查询。成功后读回权威状态再提示一次，暂时读不到状态就继续确认。被拒按原原因提示一次，下一次主动操作使用新请求号。未受理时恢复入口，手动再试沿用原请求号和载荷。处理中继续查询，系统不自动重发。
- 回执无法确定或读失败时，回退到三次连续一致、间隔至少 5 秒的权威状态读取。旧后端接口不存在时停止查回执，沿用原有状态读回规则。
- 异常2：Given 抵扣/价格缺失、资格拒绝、库存不可购或容量已满 When 操作 Then 明确结果和恢复入口，禁止无效提交；未知金额显示“-”。
- 异常3：Given 购机中余额不足、报价增加或结果不明 When 确认 Then 保留既有失败反馈/原意图恢复，不创建第二订单，不把预计值作为扣款依据。
- 异常4：发出开通或取消前，按账号保存命令种类、原请求号和发出前的领取单号。开通另存原载荷，包括设备名及已确认的商品 ID 和条款版本（若接口提供）。关页、重启或登出后再进入同一账号时恢复未结命令并继续查询，其他账号不显示这笔确认或提示。

**③ 数据字典+生成规则**

| 字段 | 类型 | 生成规则/约束 |
|---|---|---|
| claimNo/version/state | string/number/enum | 服务端权威，客户端只读缓存，不自行生成正式领取单 |
| claimedAt/expiresAt/graceEndsAt/extendedEndsAt | epoch ms | 领取快照与服务端状态推进；EXTENDED仅延长抵扣保留，不继续产出 |
| shadowUsdt/shadowNex | number | 已累计试用收益，购前不属于可提现钱包 |
| offsetUsdt/remainderUsdt/priceUsdt | number | 本人试用设备的权威金额；购买其他设备的金额读该款报价（FEAT-TRIAL06）；缺失不按当前活动配置反算可用值 |
| estimatedOffset | number | 配置日收益×领取时长再受配置上限约束，仅标预计 |
| eligibilityReason | enum | 既有原因及capacity-full，最终是否可领以canStart为准 |
| orderNo | string | convert原子交易返回；幂等重试复用原意图，不在客户端伪造正式订单 |

**④ 状态机+禁止动作**
ELIGIBLE → 确认/激活中（客户端瞬态）→ ACTIVE → GRACE/EXTENDED → FAILED；ACTIVE可主动取消至CANCELLED（有进行中的外部付款或余额付款结果未知时不提供取消）；ACTIVE/GRACE/EXTENDED可主动购机至REDEEMED。激活成功反馈不是新增业务态。禁止未读回成功显示成功、自动扣款、预计当余额、终态继续计入试用槽。再领资格沿用服务端冷却政策，本功能不修改。

**⑤ 多状态覆盖**
默认态展示真实状态与下一步；空状态为可领介绍或明确结束状态，不留空白卡。加载态保留布局骨架/已确认只读快照。报错态未知金额显示“-”，提供重试或设备管理出口；极限态覆盖长商品名、320宽、三语、明暗、最后一天与减少动态。

**⑥ 点击流矩阵**

| 触发 | 目标 | 反馈 |
|---|---|---|
| 首页领取 | 领取确认 | 查看产品、时长、预计值，关闭/取消可用 |
| 首页已领取状态卡整卡 | 试用详情/设备管理；符合再领资格时仍为领取确认 | 延续既有状态路由，移除重复独立按钮；错误重试不触发整卡路由 |

#### [FEAT-TRIAL04] 试用机位与容量

**① 用户故事**：作为持有正式设备并正在试用的用户，我想在队列和设备管理看到试用机位，以便查看时间、抵扣与转购，同时保留所有已购设备。

**② 验收(GWT)+异常路径**
- Given 实际激活数2、无订单预留且ACTIVE试用预留1 When 查看首页/赚取/管理 Then 三处槽位均为3/容量上限，正式Online设备数仍为2且只有一个试用行；不向正式设备数组注入伪资产。
- Given 实际激活数4、订单预留1、试用预留1 When 展示 Then 权威总占用为6/6，不重复叠加试用、不显示空槽；订单预留不生成设备或任务，正式Online设备数仍为4。
- Given 正式占槽5且试用1 When 转购 Then 仍为6，试用行退出、真实设备增加一次；重复请求不重复扣款或造设备。
- 异常1：Given 已满容量 When 领取、普通激活或下单 Then 服务端拒绝额外占槽；现有已购设备不消失。
- 异常2：Given 试用读取失败 When 显示设备 Then 同账号已确认正式设备保持可见，槽数未知；试用金额未知、动作停用且可重试。
- 异常3：Given 到期或取消 When 服务端状态推进 Then 只释放相应试用槽，不删除已购设备；GRACE/EXTENDED继续保留一个抵扣槽直到终态。

**③ 数据字典+生成规则**：正式设备id/instanceNo来自设备接口；试用展示key为独立呈现标识，不用于设备激活/收益/任务接口。`GET /api/devices/earnings` 顶层与Home overview的`onboarding`提供 `slotCap`、`reservedSlotCount`（订单预留）、`trialSlotCount`（试用预留）、`slotsUsed`（总占用C）；实际激活N从同一fleet的真实激活实例统计，Home的`onboarding.activeDevices`仍为N。`C=N+订单预留+试用预留`，槽位条、空槽与容量守卫取同一fleet epoch/revision接收的权威`slotsUsed`，不能再叠加本地试用，也不能被Home独立旧快照覆盖。旧后端缺字段时保留既有`N+已确认试用预留`回退：reservedTrialSlots ∈ {0,1,unknown}，按已确认有效生命周期判断，未知不得当0；容量事实不全时关闭新增动作，不伪造预留或空槽。

**④ 状态机+禁止动作（2026-10-30 更新）**：沿FEAT-TRIAL03；CLAIMED/ACTIVE/GRACE/EXTENDED占一槽，终态零槽。Cloud Share 与手机、PC、Box、Rack 按实例共同占用最多六个激活槽位；试用转换仍在锁定账号的同一事务中按原规则置换预留，不额外占槽。禁止重复占位、让 Cloud Share 免槽绕过上限或隐藏已购设备腾空间。本次取代该节旧版“禁止把 Cloud Share 误当物理槽”的免槽口径，历史验收证据保持。

2026-10-30 容量补充：已购设备选择等待任务完成后停用时，在实际停用确认前仍保持已激活 Online 并占一槽；不能仅凭 `pendingDeactivate` 释放正式容量或绕过六槽。试用转购继续置换原有一个有效预留，读取失败和排期停用均不能虚构空槽。

容量投影沿用既有账号epoch/revision隔离；换号、重绑或业务写入后，旧响应不得覆盖较新占用或放行当前领取/转购。只有权威读回确认生命周期与容量转换后更新占用，不把订单预留当作正式设备或执行任务依据；原六槽上限、试用单幂等恢复与置换交易规则保持。

**⑤ 多状态覆盖**：默认试用行沿所在队列的普通设备行呈现机型，小图上方增加“试用”角标，标题仅机型名；确认运行显示在线，抵扣保留期显示离线，读取失败显示状态未知，右侧保留相应剩余时间。当前/预计抵扣、进度、规则及购机放在展开区或详情，不在默认队列额外展开。赚取页共用单行展开状态，试用与正式设备不能同时展开；首页整行进入详情。管理页试用与已激活设备合并显示，数量包含试用行；正式设备展开后保留规格、置换及停用操作，试用展开保留取消确认；待激活及状态待确认设备独立分组，接入入口位于设备列表之后。空状态没有试用行但保留正式设备或添加入口。加载保留已确认设备/骨架，报错在展开区提供重试且不把未知计数归零。
