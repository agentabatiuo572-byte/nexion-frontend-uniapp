# 包 z8 · 冲正分录的时间戳 —— 红测台账(2026-08-12)

## 0. 这个包修的是什么

失败提现退还已烧 NEX 的**冲正分录**(`+N NEX`)盖的时间戳是**提现提交时刻**,不是**退款发生时刻**。

链条(三处代码,一个后果):

| 环 | 事实 |
|---|---|
| 生产者 | `App.vue` 的 ⓪ 对账段 `postReceiptForAccount(app.accountKey, drafts, wd.submittedAt)` —— **整组**分录共用一个 `atMs` |
| 落账 | `bills.addManyForAccountOnce` / `addMany` 把那个 `atMs` 赋给**本批全部新行**的 `ts` |
| 渲染 | `pages/me/wallet-bills.vue` 按 `b.ts` **分月分组**并显示日期 |

后果:7 月提交、8 月退还的那笔,「退回 N NEX」落进 **7 月**那一组、贴在当初「烧掉 N NEX」那行旁边。
用户在 8 月的账单里找不到钱回来的记录,而钱包里的 NEX 确实是 8 月变的 —— **两个口径对不上**。

`withdrawal-bill-drafts.ts` 与 `App.vue` 的注释本身就写着「补记要盖单据的提交时刻,否则账本给自己的
历史标错日期」。这条规矩是对的,而这条冲正正好是它的**反例**:它不是提交时发生的事。
两个独立审计 agent 各自单独点了这一条。

## 1. 修法(四层,一条线)

| 层 | 改了什么 |
|---|---|
| 契约 | `nexRefundedAt`(ISO-8601,退款发生时刻)进 §4.2 响应表与 §4.6 ② 字段表,与 `nexRefunded` **成对下发** |
| 解析 | `parseSubmission` 宽松收:缺失 / 形状不对 = **当没给**(不是 0 —— 0 是 1970),不抛协议错;先按 `YYYY-MM-DD` 卡形状再 `Date.parse` |
| 落盘合并 | `mergeWithdrawals` 里金额与时刻**整对**取自同一份快照(`pickRefundEvidence`),不各取各的 |
| 落账 | `ReceiptDraft` 加可选 `atMs`(**构造期字段,不落盘**);`addMany` / 直写盘两条路径都用 `d.atMs ?? ts` |
| 构造 | `withdrawalBillDrafts` 的冲正行带 `atMs: nexRefundAtMs(wd)` —— 这一族里唯一不发生在提交时刻的一行 |

**回落规则(显式定,写进注释与规格)**:拿不到 `nexRefundedAt` 时盖**客户端得知退款的此刻**,
**明确不沿用提交时刻**。真值一定落在 `[提交, 现在]` 里而客户端只知道两个端点;取「现在」最坏晚一个
轮询周期,取「提交」可以早几个月、且会让冲正行与被它冲正的那行同刻同组 —— 正是本包要修的形态。
服务端给的时刻**早于提交**时走同一条回落(退款不可能发生在下单之前)。

时钟**不做成入参**:那等于把「盖哪个时刻」的决定权交回调用方,而本包的缺陷正是调用方
(`App.vue` ⓪)用 `wd.submittedAt` 盖住了整批。决定留在唯一构造处。代价照实说明:
`withdrawalBillDrafts` 因此**不再是引用透明的纯函数**(文件头注已改),但仍不碰 store / i18n。

## 2. 门(`selfcheck-withdraw-nex-refund.mjs` ⑬,45 条断言 / MIN_PASS 45)

| 面 | 断言 |
|---|---|
| 主格 | 服务端给了时刻 → 冲正行 ts **跟它走**、**≠ 提交时刻**;与「烧掉」行落在**不同月分组**(抠 `wallet-bills.vue` 的分月键出来跑,先剥注释,不重写口径);同批其余两行**仍**盖提交时刻;`atMs` **不落进**账单行(内存 + 盘上都搜) |
| 判据自证 | 抠出来的分月键**恰好是月粒度**(同月同键 + 跨月异键)—— 抠错成精确到分的那个格式化器,「落在不同月」会退化成一条恒真的自证 |
| b 回落 | 没给 → 落在 `[t0, t1]` 观测区间内,且 ≠ 提交时刻 |
| c 越界 | 时刻早于提交 → 当没给,回落此刻;不许落在提交之前 |
| f 换号 | 跨账号**直写盘**那条路(`addManyForAccountOnce` 的另一段代码)同样按单条时刻落 |
| d 解析 + 咽喉 | ISO / 只到日 → epoch ms;`"3"` / `"2026"` / 裸数字 / `true` / 垃圾 / 缺失 → 当没给且不抛;**解析结果真的进得了单据对象**(`toCanonicalWithdrawal`) |
| e 合并 | 金额与时刻**成对**保留;胜出方自己没有退款事实时两个都从证据那份带过来;金额打平时取**更完整**(带时刻)的那份 |

## 4. 🔴 红测自己抓到的三件事(不是走过场)

1. **⑤⑥⑦ 第一版一个都没落地** —— 本仓源文件是 **CRLF**,而我的跨行变异串写的是 `\n`,
   一个都命中不到:**文件原封不动、门照样绿**。如果红测只报「红/未红」两态,这会被读成
   「门没抓到」,结论正好读反。现在变异没命中与未判红**分开报**,且写入后要复核文件真的变了。
2. **⑪ 当时没判红** —— 我写的 `pickRefundEvidence` 有一条「金额打平时取更完整的那份」的分支,
   而 ⑬e 的三个用例里证据侧金额恒**严格更大**,那条分支**一次都没被走到**。
   按本仓规矩(删了没红 = 先问它死没死),补了「金额相同、只有一份带时刻」的用例,⑪ 随即判红。
3. **咽喉那条断言第一版是空转的** —— 我原想用 `submit()` 证「字段穿得过解析」,而门里的
   `withdrawalApi` 是**桩**,压根不经过 `parseSubmission`:拿到的是原样 ISO 字符串。
   这与 z6 审计打出的第 3 条同型(自称穿过解析层、实为空转)。改成喂真 `createWithdrawalApi`
   再过真 `toCanonicalWithdrawal`,咽喉才真的被钉住。
