# 改动② 待证伪提案 — 让「钱 + 收据」一次落盘

> 状态:**待证伪**。按铁律「`[机制]` 改动先派人证伪修法,不是修完再验」,本文是交给独立 agent 的提案,不是已定方案。
> 分类:**`[机制]`**(改存储归属 + 改写盘路径 + 改并发语义),不是 `[机械]`。

## 一、要解决的那件事

一次资金变动现在写**两次盘、两个 key**:

| 顺序 | 谁写 | 写到哪 | 并发方案 |
|---|---|---|---|
| 1 | `app.persistAccountSnapshot()` | `nexgrid-account-cloud-v1` | 三路增量合并 |
| 2 | `bills.persist()` → `writeAccountRow` | `nexgrid-bills-accounts-v1` | 裸读写(LWW) |

两次之间没有事务。进程在中间没了(切后台被回收 / 关标签页 / 刷新),就落下**钱变了但没凭证**或**有凭证但钱没变**。
`uni.setStorageSync` 是单 key 的,**只要还是两个 key,就不可能原子**——这是物理约束,不是实现没写好。

## 二、提案(相对 v2 §三收窄,不搬内存归属)

设计 v2 原写的是「把账单内存归属搬进 `app.ts`,`useBills` 降级成门面」。回源读 `bills.ts` 后我改判:**那一步不必做**,而且它会踩 P-031(store 之间不互相 import)。

改成三小步:

1. **账单数组仍归 `useBills`**,11 个消费者一行不改;
2. **删掉 `bills.persist()` 的独立写盘**——账单不再自己碰磁盘;
3. **快照里带上 `bills` 字段**,由 `src/lib/money-receipt.ts` 里那个**已经存在、已经被机器门焊死的收据咽喉**合成一次写入:
   在内存里改完钱、追加完账单,再调**一次** `persistAccountSnapshot`。

`money-receipt.ts` 本来就同时 `useApp()` 和 `useBills()`,它在 lib 层不在 store 层 —— 这条路径不新增任何 store 互相 import。

**为什么由它合成**:全站资金路径已被 `selfcheck-money-receipt.mjs` 强制收敛到这个咽喉(白名单只剩 3 处例外)。
把事务边界放在咽喉上,等于**复用已有的那道门**来保证「没有绕过事务的资金写入」,不必再造一道新门。

**配套已就位**:`selfcheck-snapshot-literals.mjs`(commit `e02d50a`)守着「快照三处字面量字段集必须一致」。
`bills` 是新字段,三处漏一处就会被它当场判红 —— 这正是先焊它再动的原因。

## 二·补 — 顺带清掉的死字段(证伪 agent P2-11,已回源坐实)

## 四、请证伪这五问(逐条给「可以照做 / 需要修正 / 不可行」)

1. **与已有硬约束冲突吗?** 具体点名哪条、在哪行。重点看:三路增量合并对数组字段怎么合(`bills` 进快照后,两个标签页各追加一笔,合并规则会不会丢一笔?)、P-031、账号作用域。

3. **会让哪条已有流程卡死?** 重点:`addForAccount` 是**跨账号直写**(写别人的行、不碰 `bills.value`)——账单进了「当前账号快照」之后,这条路径还写得进去吗?`bindAccount` / `hydrate` 的时序?旧 key 里的存量账单怎么迁移、迁移失败会不会显示成「账单全没了」?
