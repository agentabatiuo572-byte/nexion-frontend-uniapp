# 越南银行账户提现（2026-09-15）

用户授权补齐 HDPay 代付；仅 test 候选，真实出款默认关闭。不更改 USDT 提现原路径。

## App 入口与接口

钱包提现页新增 `/pages/me/wallet-withdraw-bank`。银行账户、开户姓名、短信验证用于绑定；服务端决定银行可用范围、生效时间及再次变更时间。银行卡号仅展示掩码，不写浏览器持久层。

以下端点均在 `/api/withdrawals/bank` 下，且由当前已认证的 App 用户限定所有权：

| 方法与后缀 | 用途 |
| --- | --- |
| GET `/config` | 通道是否可用、银行列表、当前收款账户掩码 |
| POST `/beneficiary/otp` | 专用绑卡短信挑战 |
| POST `/beneficiary` | 绑定银行账户 |
| POST `/quotes` | 获取不可变的金额、手续费、汇率、到账 VND 与期限 |
| POST `/orders` | 按报价提交一次提现（固定幂等键） |
| GET `/quotes/{quoteNo}` | 恢复结果不明的原请求 |
| POST `/quotes/{quoteNo}/abandon` | 服务端取消未提交报价；已提交时返回原订单 |
| GET `/orders/{withdrawalNo}` | 查询本人原订单 |

提交前只持久化当前账号的报价编号。响应丢失后隐藏提交入口，先查原单；不得生成新键重发。确认银行打款与接口受理是不同状态。失败退款由后端共享账务处理器执行，前端不改余额。

## 验收

`scripts/bank-withdrawal-runtime.mjs` 纳入现有提现回读浏览器验收：真实页面、路由和 API 解析器，仅隔离网络传输。覆盖报价、响应丢失、查询恢复且不重复提交、处理与成功区分、取消报价、关闭通道。网络桩不代表供应商真实打款验收。

完整仓库门禁仍必须通过才可提交和发布。新页面不属于旧 5174 原型的 32 页镜像；原页面样式对齐保留，仅授权的银行卡入口更新模板指纹。
