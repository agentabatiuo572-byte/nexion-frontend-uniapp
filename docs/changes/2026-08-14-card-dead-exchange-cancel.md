# 卡:「撤销兑换单」是条死路径 —— 函数写好了,没人调

**发现方式**:2026-08-14 逐条核 86 条台账欠账时,`/api/exchange/:param/cancel` 一开始被我
判成「产品缺口」(用户能撤销但 PRD 没写)。**回源核到第三层才发现判错了** —— 用户根本点不到。

---

## 事实

`src/pages/me/wallet-exchange.vue`:

- 第 230 行定义 `async function cancelRemoteOrder(exchangeNo)`
- 它里面第 234 行调 `exchangeApi.cancel(...)`,幂等键、失败态、错误码一应俱全
- **全文件搜 `cancel`,只有定义处这一处命中;模板里没有任何绑定**

也就是说:**没有任何东西调用 `cancelRemoteOrder`**。用户在兑换页看不到、也点不到「撤销」。

## 这是什么

与本轮开头删掉的那个卡时代早购镜像**完全同型,只深一层**:

| | 早购镜像(已删) | 本条 |
|---|---|---|
| 接口方法 | 有 | 有 |
| 接口方法的调用者 | **无** | 有(`cancelRemoteOrder`) |
| 再上一层的调用者 | — | **无** |

**所以接口台账门看不见它** —— 那道门问的是「这个地址在代码里有没有被引用」,答案是「有」。
它答不了「这条引用链最终有没有人走」。**静态引用存在 ≠ 可达。**

## ⚠️ 不要顺手把 CANCELLED 展示一起删掉

同文件第 401 行有 `CANCELLED: t.value.exchange.swapCancelledReason` —— 那是**展示**侧,合法且必须留:
服务端仍可能把单据置为已撤销(到期、风控、运营干预),页面要能如实显示。

**死的只是「客户端发起撤销」这一条路**,不是「撤销这个概念」。

## 建议

两条路,**我的推荐是先问产品要不要这个功能**,而不是直接删:

| 选项 | 代价 |
|---|---|
| **A. 补上入口**(推荐先问) | 若产品确实要「用户可撤销待成交兑换单」,那缺的是 UI 入口 + PRD 一节;后端接口看起来已经备好了 |
| **B. 删掉死函数** | 若产品不要,`cancelRemoteOrder` 与接口方法一起删,并撤掉台账条目 —— 与本轮开头那笔同样的处置 |

**不建议**在没问产品之前直接删:与早购镜像不同,这条的接口签名、幂等键、错误处理都写得很完整,
像是**有意准备但入口没接上**,不像纯粹的搬运残留。判断它属于哪种,需要产品侧的意图,代码看不出来。
