# 展示数据分层缓存

日期：2026-11-02。适用于正式 App/H5，补充并调整《五 Tab 快切保护》。缓存只减少展示读取，不提供操作资格。

## 数据与有效期

| 数据 | 保存方式 | 更新规则 |
|---|---|---|
| 团队文字邀请码 | 按账号、API 环境和地址持久保存 | 首次服务端确认后复用；后续正常响应确认变化才替换；不因奖励加载或失败清空 |
| FAQ、课程列表与内容 | 内存 5 分钟，按账号/会话、语言、分页或课程 ID 隔离，跟踪服务端内容版本 | 服务端发布版本保留在结果中；新读取确认版本变化使相关旧结果失效；重试/手动刷新强制读 |
| 首页收益、设备、奖励、支付设置摘要等动态展示 | 内存 5 秒 | 成功后计时；短时返回复用，过期后下一次可见读取更新 |
| 任务配置、头像 | 内存 60 秒 | 配置的全部必要请求成功才算成功；头像须真实读取成功，合法空头像也算成功；服务端修改回执更新展示 |
| 已有行情、任务分配 | 保留既有 30 秒、60 秒规则 | 手动刷新及操作后的权威回读继续走各自强制入口 |

五 Tab 既有 1 秒内 3 次变化、3 秒快切保护保留；只对默认 5 秒动态展示延长复用，内容及 60 秒数据不因保护超过其有效期。没有后台定时刷新；有效期结束本身不触发请求。同对象在途读取共用。普通失败只在同一次访问内合并 1 秒，不作为成功缓存；HTTP 429 继续遵守 Retry-After，手动刷新不绕过服务端限流。

## 展示与刷新

- 主页面、分享海报等只读消费者通过 Store 的 ensure/read 入口读取配置、头像、首页、设备、收益释放摘要、支付设置摘要和已发布内容。多个消费者使用同一份读取结果。
- 首页待办等纯展示响应不会因无关业务写入被永久留在初始骨架；账号、会话和可见页面隔离继续生效，待办入口不作为操作资格。
- 同账号、同服务已有有效内容在后台更新期间保持可见，更新成功后整体替换。首次读取仍显示正常加载状态。网络/临时服务失败可保留已确认展示，但不能当作新请求成功；认证、权限和协议失效按现有业务撤销展示。
- 切换账号、会话归属、服务时隔离结果并丢弃迟到响应。语言变化不会复用另一语言的内容。页面刷新只处理当前可见页，不触发隐藏 Tab 的读取。
- 下拉刷新、显式重试均绕过展示有效期。FAQ/课程的手动刷新清理对应内容窗口，动态展示刷新使窗口失效并重新执行当前页读取。

## 实时操作边界

支付、提现、领取、设备操作、购买及执行前的资格查询，仍调用实时 API。已核实的置换资格/报价及客服连接票据 POST 属于实时读取，不按业务写入清掉其他展示缓存；真实业务写入继续使动态展示失效。支付设置摘要只包含展示字段，与弹层中的操作状态分开，不能提供 credentialVersion 或支付授权。

课程内容 GET 可复用，但每次开始学习仍实时执行 start 并核对课程 ID/版本；成功回执更新详情并使目录进度重新读取。答题、完成、回执查询、异常恢复和权威回读不缓存。答题/完成后清理列表和详情展示，包括结果未确认的失败场景，避免旧奖励或旧进度被当作新结果。

## 发布版本边界

本轮不增加后台版本探测接口。运营发布后的内容在真实读取发现新课程版本、手动刷新或 5 分钟后下一次读取时更新；不承诺发布瞬间推送。商品目录的运行版本变化不会使无关 FAQ/课程内容失效，操作仍受各自实时版本校验约束。内存缓存随 App 进程重启消失；邀请码按既有持久规则恢复。
