## 付款方式与金额

- 正数应付可选钱包、银行卡或 USDT；USDT 选择 BEP20 / ERC20，未配置渠道及网络不列出。单一可用网络占满一行。配置读失败沿用 App 的报价校验与自动重试，明确未配置后隐藏。
- 只有钱包需要六位 PIN。第一次设置两次确认后，再输入本笔 PIN；设置成功不直接付款。外付不读 PIN，不受钱包余额和 PIN 锁定影响。零应付权益仍走钱包确认与 PIN。
- 外付按服务端本金、渠道费与网络费计算总额；ERC20 网络费由用户承担，外部钱包另付 ETH Gas；BEP20 外部钱包另付 BNB Gas。银行确认/等待/结果显示 `$`，银行支付页之外不展示 VND 与锁定汇率。
- 原业务六位金额、两位收款本金、舍入差额、VND/FX 和配置版本保留在 intent 快照供核验；恢复不依当前全局牌价重算。
- 普通、订单详情与活动成功卡优先显示 `paidTotalUsdt`，未提供时回退订单金额。字段在 API 响应边界校验，内部按类型传递。后端是否提供该字段需部署联调确认。

## 时间、提示与恢复

- 付款选择页显示原单倒计时；钱包不足显示差额并进入带原单上下文的充值，余额足够后返回原单支付。
- 报价提前 30 秒刷新，失败按 3/6/12 秒递增至 30 秒；intent 每 5 秒读，失败按 5/10/20/30 秒退避，后台暂停、前台立即读取。
- 服务端订单/intent/deadline/银行 expirationTime 中最早时间截止付款；确认宽限不允许新增转账。截止或 `paymentAllowed=false` 后隐藏付款指引，等待权威结果。
- USDT 页显示网络、二维码、地址、总额和倒计时；到账后显示资金已收到。银行确认后在 UVEL 页头下嵌入受信任支付页。
- 付款前、时间不足、离开、超时、银行失败、人工核对、迟到款与交付异常使用居中提示。已交付后的额外到款只显示核对，不自动退款或补钱包。
- 按账号保存 kind/key/quote/intent 和网络；刷新恢复查询原 intent，不创建替代单。报价明确拒绝也先按原键读；未明结果不重报价。原创建命令、KEEP 与置换命令优先恢复，只有权威允许时显式同键继续。
- 钱包 PIN 拒绝后保留原单，取消前确认付款未执行；订单处理中的取消阻断显示原因。支付回执核验后先祝贺购买，再显示服务端激活或入库事实。结果动效不模拟交易。

## 列表与详情

列表待付款行显示剩余分钟和「继续付款」，详情显示原单倒计时，操作固定在底部。外付中的订单继续原 intent。关闭订单显示服务端 closeReasonCode；未到达的进度节点只保留点。Lite 原摘要、图片目录、分页和导航保留。

Lite 每个页面都有自己的全局弹窗宿主：切换页面时同步关闭离开页的付款弹窗，避免延迟关闭误伤详情页刚恢复的原 intent；切去银行或钱包 App 只暂停读取，返回后继续。列表续付遇到原命令回查尚未结束时，等回查解锁后使用已完成的原单读取结果。

## 充值与已知 App 问题

银行未配置且历史单读完后没有待付款/核对单时隐藏；已有银行单继续可达。页面本身读取配置，重新启用可恢复。USDT 仅探测选中网络，未配置后隐藏并切换，重返或重试重新探测。新充值本金只允许正整数；历史小数单不重建、不改变原快照。

- BUG-058：充值网络选项显示当前选中网络的费用，未选中网络费用可能错误；保留 App 行为。
- BUG-060：`channel=bank` 深链可能选择已隐藏的银行分段；保留 App 行为。

## 预览与验收边界

`scripts/lib/purchase-payment-preview-fixture.mjs` 与既有 PIN/checkout fixture 提供隔离付款、到账、隐藏通道和恢复场景；状态面板 `/preview`、API `/__demo/state`，端口 5602。正式源码无预览分支。钱包默认首次设置 PIN，可用 `/__checkout/state` 的 `resetPin` 重置本地 fixture。

预览不是已部署 TEST、真实短信、支付机构或链上验收。保留现有测试文件，不运行单元测试；以 `npm run type-check`、`npm run build:h5:prod` 及真实页面流程检查为本批验证方式。具体执行结果、未建模流程与遗留风险随交付报告记录。
