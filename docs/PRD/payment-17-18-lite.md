# H5 Lite：钱包支付密码与外部订单付款

## 范围

本轮从 App 支付实现定向同步现有 Lite 的普通下单、订单详情续付、组合购买、活动购买、试用转正、升级置换和容量购买入口。保留 Lite 原页面模板与导航、手机购买限制、隐藏质押入口和网页下载分流；不引入原生推送、原生激活或 App 整分支差异。

## 支付方式与金额

- 正数应付进入统一支付方式选择：钱包余额、HDPAY 银行卡、USDT-BSC。只有钱包余额付款需要支付密码；HDPAY/BSC 不读取或提交 PIN 字段，不受 PIN 锁定或钱包余额不足限制。
- 零应付权益继续使用钱包确认与 PIN，不创建零金额外部收款单。
- 外部支付的商品本金、渠道百分比加固定费用、BSC 网络确认费、总额、配置版本、有效期和 HDPAY 锁定汇率均读取服务端报价。HDPAY 不收网络确认费，BSC 外部钱包额外 BNB Gas 不包含在报价总额。未知费用配置不能当免费。
- 保留原业务六位精度；支付小计按服务端两位金额，回执校验两者舍入关系及支付方式。HDPAY 整数 VND 使用 BigInt 显示。充值本金要求正整数；直付本金和手续费允许合同约定的小数。
- 原付款单恢复费用区读取 intent 持久快照，包括锁定 FX、整数 VND、六位原业务金额及带符号的本金舍入差额；不查当前全局汇率或重新报价。已提供金额/差额须相符，非法 FX 或矛盾快照关闭付款指引并保留原键查询；历史未提供原金额/差额时不推算。

## 钱包 PIN

个人中心安全组新增支付密码入口，复用已实现的六位数字 PIN 设置、修改、锁定与绑定手机号找回流程。首次钱包支付依次设置、二次确认，再重新输入本笔支付 PIN；设置成功本身不授权付款。输入清空、页面隐藏、账号变化和退出登录遵循同一账户生命周期，不自动重试携带 PIN 的失效认证请求。

## 原订单与恢复

- 外付基于已存在的原业务订单或冻结报价，不先充值钱包，不触发额外钱包扣款。五类业务沿用原键、原身份和原金额；已交付业务回执必须与原请求匹配后才能接续结果页。
- 创建响应丢失时保存账户范围内的 kind/key/quote/intent 指针，恢复先查原结果。关闭、切页或重新登录不自动重建支付。容量购买保留原操作及完整报价，旧 KEEP 命令仍以原键查询；只有服务端明确允许同键恢复时才显示显式继续。
- HTTP 409 的费用策略变化、报价过期、业务定价变化，以及 HTTP 503 的费用未配置，均先查原键。只有该查询明确无原单才允许重报价；通用 409/503/504、查询失败和未知结果继续保留原身份。
- EXPIRED 与 MANUAL_REVIEW 不显示付款地址、二维码或前往付款。原业务已交付后出现额外到款异常，保留原交付事实与人工核对提示；不自动退款或补钱包。
- 外付记录仅在订单列表/详情提供恢复入口。已有 HDPAY provider hosted 页面保持原跳转方式。

## 充值

USDT-BSC 最小充值额来自服务端已审批的 Cregis 政策，HDPAY 最小充值额来自现有服务端权威配置；页面显示两位金额，输入与创建均限制正整数，重新读取每日额度等原有校验保留。

历史小数充值单可以按原身份读取其状态和 hosted 快照；点击重建返回空白整数输入并说明格式，不提交小数新单、不替换历史快照。服务端仍负责原键幂等查询及新请求金额/最低额最终判定。

## 验证边界

本地类型检查、定向行为测试、H5 构建及 loopback 隔离浏览器用于候选验证，不能替代已部署 TEST、支付机构或链上验收。本轮不进行真实资金或短信，源码交付与部署验收分开记录。

## 成功图标兼容核验（2026-10-31）

App 成功结果绿圆无勾的问题来自其新 `CheckoutResult` 图标缺少明确尺寸。Lite 当前沿用 `checkout.vue` 的内联确认结果，勾已声明 32px 宽高，符合现有原生 SVG 桥接条件，不引入 App 的新结果组件，也不改动 Lite 模板、首单庆祝、付款及跳转策略。

新增回归直接读取 Lite 真实确认分支，检查原生构建将勾转换为 `NxNativeSvg` 并保留路径，H5 构建继续保留原 SVG。该核验不代表新包真机或已部署 Lite 页面验收；交付仅含回归与本说明。
