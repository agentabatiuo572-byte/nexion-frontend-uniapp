## 日常开发和验收

1. fetch 后核对分支、远端和工作区状态，从最新 `origin/h5-lite` 开始，只提交本任务内容，保留无关改动。
2. 按改动做必要验证；页面改动还需 TEST 实景验收。验证后正常提交、推送 `h5-lite`，不自动推进正式分支。
3. 验收完成后向用户提供待合入提交、差异、验证结果和未完成项。测试通过及其他批次的批准均不构成本批正式合入授权。

## 用户批准后的正式合入

1. 取得用户针对本批 H5 Lite 变更的明确同意，再 fetch 并核对批准范围是否仍与远端一致。测试分支若增加未批准内容，应重新确认范围，不能顺带合入。
2. 从 `origin/h5-lite-main` 准备隔离候选，优先快进到已批准的测试提交。出现正式分支独有提交或冲突时，先检查差异和解决方案，完成相关验证，不强推或覆盖。
3. 正常推送 `h5-lite-main` 后，读取远端引用核对目标提交和包含关系，确认本地测试工作树及无关改动保留。若正式分支已包含测试分支全部提交，无须重复合入。
4. 正式发布只选择已批准的 `h5-lite-main` 提交，测试发布使用 `h5-lite`。合入代码与部署是不同动作，分支建立不触发本任务的线上部署。

跨分支不使用整树复制。App 共享修复应经过审查，分别移植到产品线测试分支，保留 H5 Lite 裁剪与 H5 原生能力限制。

## 环境配置

分支决定发布的代码版本，接口配置决定连接的服务。当前 H5 优先使用构建时的 `VITE_NEXGRID_API_BASE_URL`；未设置时使用当前网页 origin，由部署网关转发接口。开发预览另使用开发环境代理配置。

测试发布必须核对测试域名、接口目标和实际页面请求；正式发布必须核对正式域名、正式接口和已批准提交。`dev/prod` 是构建标记，不能单独作为服务器环境的证明。不能因更换 Git 分支就宣称完成环境隔离。
